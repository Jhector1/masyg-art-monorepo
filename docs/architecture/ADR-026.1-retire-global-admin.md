# ADR 026.1 — Retire global legacy commerce administration

Status: Development migration, not an operational launch.

The v26 canonical merchant API controls catalog, store and publication by an authenticated user and an organization membership, with store grants where applicable. The former `/admin` CRUD screens and `/api/admin/{categories,orders,users}` read or mutate cross-merchant data, use obsolete Prisma columns, and have no tenant selector. Correcting their types would preserve an incorrect authorization boundary.

Therefore delete the obsolete services, routes, and pages rather than add `any` or emulate old tables. `/admin` remains a separate platform-only page with its existing MFA requirement, but performs no global commerce queries. `/merchant` remains the canonical organization-authorized commerce interface. Do not use an emergency or platform admin grant as substitute for merchant membership.

Future work: create tenant-scoped category/order/customer management endpoints using the canonical domain and explicit authorization, then restore corresponding UI inside `/merchant`. The previous global order-status mutation endpoint is intentionally removed; the paid/refunded state will only be updated from trusted payment/fulfillment evidence, not arbitrary status strings.

Bootstrap: The initial merchant account requires a 12–256 character password, entered at a terminal prompt and never sent through command arguments or logs.

This batch contains no Prisma migration and does not alter checkout activation.
